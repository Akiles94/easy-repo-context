# Gotchas
- Implementation edits are gated: no change to `src/**`, `desktop/**`, `package.json`, or build config until `advances/<ADV>/plan.md` has an `Approved:` line, and agents never write that line on their own. Enforced by `.claude/hooks/guard-implementation.sh`; rules in `CLAUDE.md`. Push/merge need `review.md` `Verdict: PASS` (`.claude/hooks/guard-git-ops.sh`).
- Every vault write goes through `session.write()` (`src/context/infra/vault-sessions.ts:SqliteVaultSessions.commitWrite()`): mutation + lineage bump in one tx, `recordSeen` only after commit. A write outside it skips the bump and sync fork detection goes blind. Failed mutations roll back via `WriteFailedSentinel`.
- Reads must not touch lineage or schema. `readSchemaVersion` deliberately avoids `migrate()` (`src/vault/infra/file-vault-store.ts`); `readLineage` migrates as a side effect, so call it only after the upgrade gate in `src/vault/application/use-cases/unlock-vault.use-case.ts`. Reader rules: `docs/vault-format.md`.
- Journal mode is `DELETE`, never WAL (`src/shared/infra/sqlite.ts:openVaultDb()`): a sync client must only ever see a single `vault.db`. Don't add modes that leave `-wal`/`-shm`/`-journal` sidecars. Evidence: `2fcf51f`.
- "Unlocked" == key in OS keychain; no daemon. Idle auto-lock is lazy, checked at session open (`src/vault/application/policies/session-guard.ts`). An entry point that doesn't open via `VaultSessions.withSession` bypasses the TTL.
- `imported` is storable but never saveable: `ITEM_TYPES` (save/MCP) excludes it, `STORABLE_ITEM_TYPES` includes it (`src/context/domain/values/item-type.ts`). Packs exclude `imported`; search includes it. Adding it to `ITEM_TYPES` lets a model mint imports.
- Imported item ids are deterministic (`src/context/domain/entities/context-item.ts:importedItemId()`); changing the hash input orphans previous imports and duplicates on re-import.
- The `generic` parser must stay out of `autodetect` (`src/importers/infra/parser-registry.ts`): its permissive match would swallow malformed official exports.
- Pack assembly and token estimate (`chars/4`, newest pinned always included, one handoff only) are a published contract (`src/context/domain/services/context-pack.ts`). Changing it means regenerating the golden vault (`VALIJA_WRITE_GOLDEN_VAULT=1`, `src/delivery/vault-format-conformance.test.ts`) and updating `docs/vault-format.md`.
- Schema change = new numbered file in `src/shared/infra/migrations/` plus an entry in `src/shared/infra/migrations.ts`; table-rebuild migrations set `backup: true`. Older readers must refuse newer vaults, and the desktop confirm screen lists `pendingMigrations()`.
- FTS terms are quoted per term (`src/context/infra/item-repo.ts`, `toFtsQuery`); raw user text in `MATCH` breaks on FTS5 syntax.
- IPC errors carry `code` only, never `DomainError.message` (`desktop/src/main/ipc/to-ipc-result.ts`); the renderer maps codes to i18n copy. Raw messages would leak paths and driver text.
- Only the passphrase and the recovery-kit text may cross IPC as secrets; the kit is read exactly once (`desktop/src/main/ipc/handlers/vault-handlers.ts`, `vault:readRecoveryKit`). Never add `keyHex` to a response type.
- Desktop source may not contain `fetch(`, `http://`, `https://`, `setInterval`, or `crashReporter` outside comments, CSS included (`desktop/src/main/infra/no-network-surface.test.ts`).
- Relocation: lock first, copy-verify-then-delete (never delete-then-copy), re-point client configs last and never undo the move on a client failure (`src/vault/application/use-cases/relocate-vault.use-case.ts`). Path semantics follow the injected `platform`, not the host OS (fix `8fd3bd9`).
- AI-client config writes must go through `installIntoClient` (backup + merge) in `src/delivery/cli/installer.ts`; a second writer loses the backup discipline.
