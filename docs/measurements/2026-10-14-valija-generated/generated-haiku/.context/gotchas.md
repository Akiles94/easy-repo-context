# Gotchas
- Every vault mutation runs inside `session.write()`. Sessions expose `projects`/`items` directly, so a save outside `write()` commits without `lineageStore.bump()` and lineage/fork logic never sees it. Ref: `src/context/infra/vault-sessions.ts:SqliteVaultSessions.commitWrite()`.
- The lineage bump commits in the same transaction as the mutation, and `recordSeen` runs only after commit. Recording "seen" first makes a rolled-back write look like a stamp this device already saw. Ref: `src/context/infra/vault-sessions.ts:SqliteVaultSessions.commitWrite()`. Evidence: its doc comment.
- `write()` rethrows non-sentinel errors instead of returning `err`. Desktop code that wraps sync import/list chains must catch them (`orStorageError`), or the throw crosses IPC as a rejection and strands the renderer. Ref: `src/context/infra/vault-sessions.ts:SqliteVaultSessions.commitWrite()`, `desktop/src/main/ipc/handlers/import-handlers.ts:orStorageError()`. Evidence: "D-9 Option B" comment there.
- "Unlocked" means the key is in the OS keychain, nothing else. Don't add a second key cache. A wrong key at session open deletes the keychain entry. Ref: `src/context/infra/vault-sessions.ts:SqliteVaultSessions.openRepositories()`, `src/vault/infra/keyring.ts:OsKeychain.setKey()`. Evidence: comment at `vault-sessions.ts:78` ("otherwise the vault is locked").
- Idle auto-lock is lazy: `SessionGuard.guard()` runs only when a session opens. There is no timer, so an idle process keeps the key in the keychain until its next vault access. Ref: `src/vault/application/policies/session-guard.ts:SessionGuard.guard()`. Evidence: its doc comment ("no-daemon TTL check").
- Keep the schema gate before `readLineage`: `readLineage` migrates as a side effect. `readSchemaVersion` must stay migration-free, or there is nothing left to confirm. Ref: `src/vault/application/use-cases/unlock-vault.use-case.ts:UnlockVault.execute()`, `src/vault/infra/file-vault-store.ts:FileVaultStore.readSchemaVersion()`. Evidence: "D-J(b)" comments.
- The CLI passes `upgradeConfirmed: true` (silent migrate). The desktop must leave it unset until its confirmation screen has run; copying the CLI call into the desktop skips the prompt. Ref: `src/delivery/cli/vault-commands.ts:unlockCommand()`, `src/vault/application/use-cases/unlock-vault.use-case.ts:UnlockVault.execute()`.
- Fork is a notice, never a resolution. On fork, unlock stays unlocked, last-seen is not updated (the warning must persist), and nothing is deleted or auto-merged. Ref: `src/vault/application/use-cases/unlock-vault.use-case.ts:UnlockVault.execute()`, `src/vault/domain/services/vault-lineage.ts:classifyLineage()`. Evidence: "Leave last-seen untouched" comment.
- Relocation: the source must be locked (empty keychain), the copy must match by sha256 before the source is removed, and the order is never delete-then-copy. Never rename, because `rename` fails across volumes (`EXDEV`). Ref: `src/vault/application/use-cases/relocate-vault.use-case.ts:RelocateVault.execute()`, `src/vault/infra/file-vault-mover.ts:FileVaultMover.copy()`. Evidence: "D-R(b)" and "§8.12" comments.
- Path containment uses the platform argument's path module (`posix`/`win32`), never host-bound `node:path`. The host version made the nesting check fail only on Windows. Ref: `src/vault/domain/services/vault-relocation.ts:pathModuleFor()`. Evidence: commit `8fd3bd9`.
- Re-pointing AI clients happens only after `relocateVault` returns `ok` and `rebuildContainer(root)` has run. The use case must not call it ("D-R(a)"). Ref: `desktop/src/main/ipc/handlers/relocation-handlers.ts:createRelocationHandlers()`.
- Imported item ids hash `(projectId, source, conversationId, chunkIndex)`. Re-importing into the same project upserts; the same export into another project creates duplicates. Ref: `src/context/domain/entities/context-item.ts:importedItemId()`. Evidence: its doc comment.
- Renderer code calls the lock-aware bridge, never `window.valija`. `withLockDetection()` is what turns a `VAULT_LOCKED` result into the locked state; direct calls skip it. Ref: `desktop/src/renderer/state/lock-aware-bridge.ts:withLockDetection()`, `desktop/src/renderer/app.tsx`. Evidence: "never `window.valija` directly" comment in `desktop/src/renderer/state/bridge.ts`.
- Leaving "unlocked" must reset the workspace view (`resetWorkspaceView()`), paired with the session-state change. Otherwise a finished relocation reopens the wizard on the next unlock. Ref: `desktop/src/renderer/state/workspace-nav.ts:resetWorkspaceView()`, `desktop/src/renderer/app.tsx` (`relocationFinished()`, `lockNow()`). Evidence: "C2" comments.
- IPC error contract: `error` carries only `code`, never `DomainError.message` or a caught error's text. The renderer maps codes to copy. Ref: `desktop/src/shared/ipc/messages.ts:IpcResult`, `desktop/src/main/ipc/to-ipc-result.ts:toIpcResult()`. Evidence: "D-V(d)" header comment.
- A new IPC channel needs four edits: `desktop/src/shared/ipc/channels.ts`, `desktop/src/main/ipc/schemas.ts`, a handler factory, and the hand-written `desktop/src/preload/index.ts`. Registration only checks main-side handlers; nothing checks the preload. Ref: `desktop/src/main/ipc/register-handlers.ts:registerHandlers()`. Evidence: comment at `preload/index.ts:48` ("never a loop over the channel tuple").
- The raw recovery key never leaves main as a value. The only key output is rendered kit text, read once via `vault:readRecoveryKit`. Ref: `desktop/src/shared/ipc/messages.ts` (recovery-kit response type), `desktop/src/main/ipc/schemas.ts`. Evidence: comment on the recovery-kit response in `messages.ts`.
